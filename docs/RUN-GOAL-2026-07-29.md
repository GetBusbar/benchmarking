# Goal: 14 honest gateways on the website by 08:00 PT, 2026-07-29

Written 2026-07-29 05:25 UTC (22:25 PT Jul 28). Budget to deadline: 9h35m.
Delete this file when the board is live and KICKOFF.md is gone.

## The definition of done, in the owner's words

"Real honest values for the cells configured per gateway, displayed on the webpage correctly. No
more fake, false, misunderstood data or not showing it. The real results, good or bad, shown for
real."

Operationally that is four claims, each of which must be machine-checked rather than asserted:

1. Every cell a gateway DECLARES gets measured, or gets an explicit reason it could not be.
2. Every published number is either a real measurement or an explicit measured-failure. `0` is a
   number; a bare `n/a` on a served cell is a defect.
3. Every absence carries a reason from the engine through the seal to the tooltip.
4. A row is all-or-nothing: fully measured, or fully empty. Never a pill over holes.

`bench-audit.py` exits 0 is the machine form of 1-3. `node --test test.mjs` + `check-consistency.mjs`
is the machine form of 4 and of "the page shows what the artifact says".

## The pipeline, with gates

Each phase has an EXIT GATE. A phase is not done because it ran; it is done because its gate is green.

### Phase A - land the fix wave (target: 06:30 UTC / 23:30 PT)
- Cross-file engine pass (opus, running): percentile unification, header-injection refusal in the
  probe/stream/reverify lanes, content-frame accounting, duplicate credential headers, the last
  fabricated `fail: 0`.
- Test-coverage sweep (fable, worktree branch `tests/coverage-sweep`): merge into main tree.
- GATE: `cargo fmt --check`, `cargo check`, `cargo clippy -D warnings` clean; site tests green;
  `bench-audit_test.py` / `charts_test.py` / `bench-dashboard_test.py` pass; commit; push; ALL CI
  workflows green. CI is the test authority, not this laptop.

### Phase B - round 2 audits (target: 07:30 UTC / 00:30 PT)
Opus/Sonnet only, against the COMMITTED tree so every finding cites a stable line.
- Fix verification (opus): does each of ~50 fixes actually fix what it claims? Proven by reverting
  the hunk and watching a test go red, not by reading the comment.
- Cross-agent contract drift (opus): 9 agents edited disjoint files but share data contracts and
  nobody audited the seams (CellStream.reason prose->token, stream_served vocabulary, Runtime
  identity shape, plateaued/load_s Option->Measurement, build_request Result, SseReader::finish
  signature, connect-timeout accounting).
- Regression lens, gate meta-audit, site/engine agreement (sonnet).
- GATE: every honesty-critical finding fixed and pushed, CI green. Latent findings go to the ledger.

### Phase C - two-gateway proof (target: launch 07:30, audited by 09:30 UTC / 02:30 PT)
`PUBLISH=0 ./run-on-ec2.sh kong one-api`. Chosen deliberately:
- one-api proves the restart-replays-commands fix (its added-latency and streaming legs failed 100%
  on the last board because the memory restart destroyed its channel config).
- kong proves the peak fix (its peak sat on the top probed rung) and the recalibrated stall bound.
- GATE, all four, no exceptions:
  1. `bench-audit.py` exits 0 on the two pulled snapshots.
  2. one-api publishes a REAL added-latency number where it previously published a hole.
  3. kong's published peak concurrency sits BELOW its top probed rung.
  4. Site builds from those artifacts and the tabs show no combo rows, no bare n/a on a served cell.
- Round 2's non-critical fixes happen DURING this run. Do not idle while EC2 works.

### Phase D - the 14 (target: launch by 11:00 UTC / 04:00 PT, landed 13:30 UTC / 06:30 PT)
`./run-on-ec2.sh` with no args, publish on. Results publish per gateway as each box finishes.
- AUDIT AS THEY LAND. Every snapshot gets `bench-audit.py --gateway <name>` the moment it arrives.
- ON ANY HINT OF AN ISSUE: diagnose first, then `./run-on-ec2.sh kill`, fix, re-run. A partially
  wrong board published is worse than a late board.
- Never run charts.py while a box is live.

### Phase E - publish (target: 14:00 UTC / 07:00 PT)
Full-board `bench-audit.py`, regenerate charts, site deploy green, delete KICKOFF.md and this file.
One hour of buffer to the deadline by design.

## The hard decision point

**If the full 14 has not LAUNCHED by 11:00 UTC (04:00 PT), 08:00 PT is not achievable.**
At that moment the honest options are, in order of preference:
1. Launch the 14 with a known-latent (non-honesty) finding still open, and log it in the ledger.
2. Launch a subset - the board publishes per gateway and deploys green on a partial board, so
   "10 of 14 honest rows by 08:00, the rest by 10:00" is a real option and is better than a rushed
   full board.
3. Move the deadline. Say so early, not at 07:55.

What is NOT an option: publishing a board whose audit is red, or skipping the two-box proof. The
entire reason today's work exists is that a board was published on the strength of an opinion.

## Failure playbook

- Two-box gate fails -> diagnose from the artifact (the absences map now names every reason), fix,
  re-run the two. Each cycle costs ~1.5-2h. TWO failed cycles blows the deadline: after the first
  failure, reassess against the 11:00 UTC gate immediately.
- A gateway fails mid-14 -> it is one box; let the others finish, re-run that one alone
  (`./run-on-ec2.sh <name>` publishes only that gateway).
- Something systemic (audit red across many gateways) -> kill the whole run, do not let 14 boxes
  burn 3 hours producing a board that cannot be published.
- Rate limit / session limit on this session -> the ledger, this goal file, and the task list are
  the handoff. Everything needed to resume is on disk, not in context.
